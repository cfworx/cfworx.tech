Management practices = organizational resources and capabilities for getting work done, drawing on all [four dimensions](/notes/it-service-management/itil-5-foundation/four-dimensions-pestle-frameworks/). This post covers the run-the-service five; the change-and-control set is in [the next one](/notes/it-service-management/itil-5-foundation/practices-change-delivery-control/).

| Practice | Purpose | Terms to know |
|---|---|---|
| Incident management | minimize incident impact, restore service fast | incident = unplanned interruption or quality drop; swarming = multi-discipline pile-on for complex incidents; major incident = high impact, immediate coordinated action |
| Problem management | cut incident likelihood and impact by chasing causes | problem = cause or potential cause of incidents; workaround = temporary impact reducer; known error = analyzed problem without a permanent fix yet |
| Service desk | THE entry point and single point of contact for users, capturing support demand | moment of truth = any episode where a user forms an impression; service empathy = ability to understand user experience |
| Service request management | handle predefined user-initiated requests smoothly | service request = pre-agreed normal delivery (password reset, software access); request catalogue = the user-facing menu |
| Monitoring and event management | observe, analyze, respond to state changes | event = any significant change of state; alert = threshold reached or failure notice |

The definitional splits are the exam meat: incident (unplanned interruption) vs problem (cause of incidents) vs service request (planned, pre-agreed). And workaround vs known error vs resolution.
